# Native Core checks

Run `bash scripts/test-native-core.sh` from the SSD checkout. The script builds the same Swift `GameSession` used by the visionOS application. All compiler caches, executables, fixture files and reports remain under `$SCAPE_WORKSPACE/Build/CoreChecks`; JSON and console evidence are in `Artifacts`.

Suites may also run separately: `fault`, `live`, `recipe`, `melee`, `magic`, `trade`, `commerce`, `transition`, `reorder`, `persistence`.

- `fault` uses its own ephemeral loopback HTTP server. It verifies action uncertainty without replay, queued-click cancellation, stale snapshots, session expiry, position-preserving recovery, malformed replies and delayed-login cancellation cleanup.
- `live` uses a new randomly named development character. It verifies movement, equipment changes/removal, dialogue progression, inventory drop/pickup and every enabled tab.
- `recipe` earns Logs and Woodcutting XP normally, then uses the starting Tinderbox on those Logs for Firemaking XP.
- `magic` casts the original Wind Strike with starting tutorial runes, requiring both Magic XP and rune consumption.
- `melee` equips an owned Bronze sword and attacks an outdoor Goblin, requiring both actual NPC damage and combat XP.
- `trade` uses two independent native Swift sessions, verifies correct offer ownership, both acceptance stages and exact final inventory transfers.
- `persistence` runs three separate native processes against an isolated fault server using actual macOS Keychain storage: initial session, fresh-process resume without another login, expired-bearer recovery without resetting location, and scoped logout cleanup. Tokens never enter artifacts.
- `reorder` verifies the same native Move and drag payload handlers used by the UI: empty-slot moves, occupied-slot swaps, unchanged other slots, conserved quantities, and rejected foreign/stale/duplicate requests. It restores the original inventory layout.
- `transition` opens the Lumbridge tower door, climbs its original ladder, expires only its own session through ordinary logout, verifies native recovery preserves the upper floor and inventory, climbs down and walks across a region boundary.
- `commerce` walks normally to the Lumbridge store and Draynor bank, sells an owned starting item, buys a Pot, deposits it and retrieves it using Withdraw X and amount entry.

The live suites change only their own new QA characters through ordinary game actions. They share the existing game world and create no privileged fixtures. Live suites log out owned sessions on success and failure. The first two isolated persistence phases deliberately exit without logout; their final phase and the shell cleanup remove only their own QA Keychain records and stop their own fixture server. The live suites require the existing private tunnel at `http://127.0.0.1:18890`; override `SCAPE_GATEWAY` for another explicitly authorized game endpoint.

These checks establish native networking and action semantics. The app's `--tablescape-test` mode separately checks rendered native meshes and integrated state in the visionOS Simulator. Core success is not physical Vision Pro tracking, pinch-input, or visual parity proof.


2. `persistence_resume` passes five checks: connection preferences survive process exit, the new process reads its own Keychain bearer, resumes with GET without another login and retains position.
3. `persistence_expired` passes six checks: expired saved bearer recovery uses `startLumbridge: false`, retains location, explicit logout deletes the remote session and clears the saved bearer, and another endpoint's credential remains untouched.

Live game servers and existing player sessions are not involved in this fixture test. ## Animation performance and GPU buffer lifetime

Run `bash scripts/test-native-performance.sh` for both checks, or pass `animation` or `pool`. The runner needs the installed Xcode Swift/Metal tools and a local Metal GPU; it downloads nothing and uses no game sessions. All generated source, compiler caches, binaries, shader copies and logs stay under `Build/PerformanceChecks` on configured storage. The animation check compiles the current animator and a frozen test-only pre-optimization reference together with `-O`. Only visionOS-only imports and surrounding UI/compositor wrappers are omitted for the macOS harness; the allocator, retirement logic and completion tracker remain unchanged. A test scaffold appended to the same compilation unit uses a real Metal shared event to hold two queued reads, checks that retirement cannot recycle their buffer, validates the three-command limit and GPU readbacks, then confirms reuse after completion. The two-view case is represented by two upload calls within one command; this is GPU resource-lifetime proof, not a Compositor Services presentation test. Results are `Artifacts/animation.log` and `Artifacts/pool.log`.
