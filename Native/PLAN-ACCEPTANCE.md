This record preserves the staged implementation and acceptance history from **2026-09-27**. Earlier tables below describe their checkpoint and can be superseded by later entries. Use [README.md](README.md) for current setup, renderer support and status.

The all-model audit covers 4,556 models/615,847 faces; selected cow/goblin/textured models passed actual Mac GPU comparisons, and simulator combat passed. These later results supersede the older statements below that device signing/installation or private bridge deployment had not happened; they do not establish complete original-game parity.

## Native-specific limits and inherited gaps

Placement currently models a convex table boundary with at most eight clip vertices; manual placement accepts four ordered convex corners. Concave tables, holes and independently modeled tabletop obstacles are unsupported. The four-corner UX uses a visible, adjustable horizontal-height guide and selection-ray intersections on visionOS; the Unity controller mode recorded controller marker positions directly. Both require a separate explicit confirmation. Geometry and source review verify the mathematical path; human placement accuracy still needs a headset.

Native floating windows follow visionOS window management. They are not copies of Unity's world-space button meshes. Original icons, portrait geometry and quest imagery/live text are reused where useful, while text/layout and control surfaces are native; Unity's exact bitmap-font/sidebar-frame/component layout is not reproduced. This is an interface adaptation; exact original sidebar pixel layout is not an acceptance claim.

Original face priorities and transparency data are retained. Both the existing Unity consumer and this Metal consumer use depth-tested material groups, so neither fully reproduces the original Java painter-order rasterizer. Representative shader/texture/alpha comparisons are still needed. The same applies to exact integer animation edge cases, override equipment, all attachment transforms, scenery lighting/shadows, roof hiding, morphing scenery and upper-floor/bridge cases identified by the inherited parity document.

Public/private chat, friends/ignore controls, official account/login protocols, exhaustive quest/skill/area coverage, dueling and every advanced inventory/trade failure path remain inherited scope limits. A generic server widget/action route makes existing scripts accessible; it does not prove every script or interface. Audio routes and playback exist, but exhaustive sound/music transitions and physical listening checks have not been accepted.

Current profiling reports rolling CPU encode/driver/GPU measurements, skipped work/upload counts, resident bytes, scene counters and bounded network latency statistics. The user reported roughly 2 FPS interaction before the fixes; the final simulator callback/scene measurements and exact-parity/GPU-lifetime checks are recorded in [PERFORMANCE.md](PERFORMANCE.md). The user selected simulator verification for now. These should guide a device trace; they are not complete allocation, GPU deadline or whole-process memory guarantees. Multiple render surfaces can contribute command completions, which must not be presented as a single headset frame rate.

## Physical acceptance sequence

1. Make the paired Vision Pro available. Build/sign/install using the team's normal Apple provisioning; retain the exact build/source and device/OS identity. Configure a trusted private endpoint using [NETWORKING.md](NETWORKING.md), then verify native login, state, assets, walk and recovery with a fresh QA character.
2. Detect a horizontal table, select it and confirm. Walk around it while the character walks across game coordinates. Confirm that the table remains stationary, the game moves inside it and clipping/picking agree at every edge.
3. Reset placement. Mark four corners, undo/re-enter one, try invalid/crossed/too-small outlines, and confirm a valid board. Check fallback height and marker visibility. Deny plane permission and exercise the supported manual flow.
4. Interrupt tracking, cover sensors or leave/re-enter the tracking area as appropriate, suspend/resume, close/reopen immersion and restart in the same room. The same anchor must recover; game content/input must remain paused while tracking is unavailable. Test explicit reset after unrecoverable anchor removal.
5. Physically perform movement, conversation, inventory item use, equip/remove, shop buy/sell, bank deposit/Withdraw X, melee, Wind Strike and both trade stages using separate test accounts. Verify menus never also activate the world and panels remain readable/reachable.
6. Record matched Unity/native views of terrain slopes, equipment, different floors, movement, projectile/impact/teleport, health/hit feedback, death and animated dialogue. Listen to region music, jingles and sounds. Record any differences separately from frame timing.
7. Run an extended session including region crossings, teleportation, reconnects, table repositioning and tracking recovery. Capture Metal System Trace, actual presentation deadlines, CPU/GPU bottlenecks, allocations, upload stalls, network latency and memory trend. Target the headset's selected presentation rate; do not substitute simulator timing.
8. Preserve the source revision, pack lock, successful device artifact, reports and valuable captures on game server with a recorded destination and checksums. Keep credentials out of that backup. Only then mark the plan's physical, performance and packaging acceptance complete.
