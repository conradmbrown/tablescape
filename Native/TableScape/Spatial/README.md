# Native table placement

`TablePlacement` is the main-actor owner of ARKit world tracking and horizontal-plane detection. `PlacementView` is its native control panel. Run `await placement.start()` after opening immersion; call `placement.stop()` on close. Reopening creates new provider instances and relocalizes the same saved world-anchor UUID. The render thread should use the stable `placement.trackingSource.queryDeviceAnchor(atTimestamp:)` handle with Compositor Services' predicted presentation timestamp.

`TablePlacementSnapshot` is a value snapshot that contains the table-to-room transform, physical X/Z dimensions, a counterclockwise X/Z clipping polygon, confirmation state, virtual mode, and tracking availability. The room/table transform never contains the player/game origin or the headset pose. A detected plane only supplies initial placement: after explicit confirmation, only that same WorldAnchor may update the table transform. Lost tracking freezes the table transform, exposes a recovery status, and consumes immersive gameplay pinches until the same anchor is tracked again. The renderer should hide game content during that recovery state. Tiny metadata stored in UserDefaults recovers physical placement across app restarts; virtual placement always remains explicitly identified.

Use `PlacementVisualization.nodes(for:)` for spatial highlighting: up to eight nearest horizontal surfaces, selected surface fill/outline, the manual height guide, and visible corner markers. These nodes already use room coordinates; render with an identity board transform and no game clipping. Its geometry cache is bounded to 96 entries. The underlying `surfaces`, `selectedSurfaceID`, and `manualCorners` remain available for custom presentation. Route setup pinches to `handleSelectionRay(origin:direction:)` in world space before routing them to gameplay. A `true` return means the input was consumed. Surface selection never confirms automatically. The four-corner path supports undo and cancellation, a configurable tabletop height, ray-plane picking, and a separate explicit confirmation button. `addCorner(_:)` also accepts directly tracked world-space points. Changing the fallback height is disabled after the first corner to avoid mixing planes.

Geometry validation rejects nonfinite values, fewer/more than four points, coincident points, crossed/concave outlines, surfaces more than 15 degrees from horizontal, noncoplanarity over 3 cm, boards smaller than 20 cm per side / 0.04 square metres, and boards over 4 m per side. Plane mesh vertices produce a convex hull; the hull is reduced inward to at most eight vertices to match the renderer's clipping budget. This convex-table assumption excludes concave tables and holes. The fallback accepts only convex quadrilaterals. The CPU picking polygon and Metal polygon must use the same snapshot boundary. The gameplay boundary clips only the X/Z footprint at every elevation. Do not discard geometry or ray hits below the player-centered Y origin: doing so makes rivers, low ground and lower floors disappear as the player climbs.

The simulator path uses an explicit virtual board. `placeVirtualTable()` samples the current tracked eye pose (or identity when unavailable), projects forward onto the horizontal plane and places the board 1.6 m ahead / 0.45 m below the eyes. Explicit virtual controls adjust distance, eye-relative height and size; Apply places it once and does not create a head-following board. An optional center argument supports reproducible fixtures. The world origin is not assumed to be the floor. Unsupported ARKit providers are never passed to `ARKitSession.run`. Real table confirmation is disabled without an active tracked device pose. Denied world-sensing permission still allows world tracking with manually defined corners when supported. `NSWorldSensingUsageDescription` is required in the app's Info.plist.

## Verification

Run `Spatial/check-geometry.sh` with configured storage mounted. Compiler caches and the check executable remain in `$SCAPE_WORKSPACE/Build`. The checks cover valid/reversed/rotated boundaries, clipping, forward/missed/parallel ray intersections, invalid geometry, bounded convex hulls, and rigid room-transform invariance. The same command also verifies north-up minimap coordinate mapping and click bounds. Logs are retained in `Build/SpatialChecks/Artifacts` on configured storage. The native sources were also typechecked against the installed Xcode visionOS simulator SDK.

Simulator compilation or playing on the virtual board does **not** prove physical tabletop tracking. Physical acceptance still requires a Vision Pro: detect/select/confirm a table, walk around it, move the game character while the table remains stationary, define four corners and undo one, interrupt tracking and recover the same anchor, close/reopen immersion, and restart the app in the same room. Permission denial and anchor-removal recovery should also be checked on hardware. No physical Vision Pro result is claimed here.

Apple references: [World-space tracking](https://developer.apple.com/documentation/visionos/tracking-points-in-world-space), [ARKitSession](https://developer.apple.com/documentation/arkit/arkitsession), and [plane detection](https://developer.apple.com/documentation/arkit/planedetectionprovider). API signatures were verified against the installed Xcode 26.6 / visionOS 26.5 Swift interfaces.
